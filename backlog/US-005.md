# US-005 — Integrate and verify sign-in through an independent relying party

## User story

As an application developer, I want a reproducible standard OIDC integration example, so that I can sign users in with WalletGate without adopting its wallet frontend stack.

## Story map context

- Journey/activity: [developer integrates and confirms the outcome](STORY_MAP.md#application-developer-and-self-hosting-operator).
- Proposed release contribution: makes the complete self-hosted evaluation release independently demonstrable.
- Ordering/dependencies: US-003 token issuance, US-004 client management and runnable setup from earlier stories.

## Acceptance criteria

Provisional outline; detail reproducibility and integration matrix before READY.

- AC-01: Following the documented setup, a developer registers two clients and runs an independent relying-party example for each. The example consumes standard OIDC endpoints and has no dependency on Next.js, wagmi, viem or WalletGate frontend libraries.
- AC-02: Signing in with the same verified wallet through both client registrations produces validated ID tokens with the same canonical address sub and distinct appropriate audiences. The relying party validates state, signature, issuer, audience, expiry and request nonce before establishing its local session.
- AC-03: Consent denial or a tampered/invalid token fails application sign-in. A second wallet yields a distinct subject, and a disabled client cannot complete new authorization or token issuance.
- AC-04: The walkthrough covers owner isolation, registration, redirect updates, consent acceptance/denial and disabling, using repeatable commands and clearly distinguishing automated checks from manual wallet/device observations. No committed secrets or paid hosted dependencies are required under the proposed evaluation scope.

## Out of scope

- Production hosting/release, operational guarantees, unrelated service-account binding and additional client/grant profiles.
- New authentication or authorization behavior beyond the preceding stories.

## Dependencies and risks

- US-003 and US-004; agree example client/runtime, local network/origin setup and reproducibility environment before READY.
- Evidence from an example establishes the tested integration only, not general OIDC certification or production readiness.
