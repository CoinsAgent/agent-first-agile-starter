# US-002 — Register independent applications with a verified wallet

## User story

As an application owner, I want to register multiple applications using my verified wallet, so that each application can integrate independently with WalletGate.

## Story map context

- Journey/activity: [owner registers applications](STORY_MAP.md#application-owner).
- Proposed release contribution: supplies independently configured clients for standard OIDC integration.
- Ordering/dependencies: US-001; map decision D5 and registration policies below.

## Acceptance criteria

Provisional outline; detail measurable boundaries and resolve policies before READY.

- AC-01: A SIWE-authenticated owner registers two applications and obtains distinct client IDs and the approved integration configuration; client IDs differ from the owner's wallet identity and each other.
- AC-02: Each application retains independent redirect URI, scope and credential configuration across owner logout/login; changing one never changes the other.
- AC-03: Unauthenticated registration, including direct backend/dynamic-registration calls, is denied; a merely linked/unverified wallet grants no registration rights.
- AC-04: Invalid redirect URIs, unsupported scopes and attempts to assign another owner are rejected without creating a usable client. Application ownership grants no access to end-user accounts or data.

## Out of scope

- Proposed: unauthenticated or dynamic registration, ownership transfer, extra client types and credential rotation.
- OIDC consent/token issuance and owner editing workflows, covered by later stories.

## Dependencies and risks

- US-001 and approved initial client profile (D5).
- Resolve registration fields, redirect rules (including local development), supported scopes, credential creation/display/storage policy and any registration limits before READY.
- Better Auth customization must preserve wallet-owner authorization for every exposed registration path.
